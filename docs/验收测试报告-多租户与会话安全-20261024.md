## 4. 本轮代码修复

| 文件 | 修复内容 | 目的 |
|---|---|---|
| `backend/src/main/java/com/dgp/common/TenantGuard.java` | 用 `LOWER(column_name)='tenant_id'` 识别租户表，并排除系统 schema，不再依赖 H2 下为空的 `DATABASE()` | 让 H2/MySQL 都能发现需追加租户条件的表 |
| `backend/src/main/java/com/dgp/admin/OverviewController.java` | 概览的字段数、调用量、失败作业、最近采集、调用趋势、最近作业按租户关联过滤 | 消除“主表为 0、子指标仍为全局值”的残留泄露 |
| `backend/src/main/java/com/dgp/common/Db.java` | 对 VARCHAR 主键的生成键返回 `0L`，不再强制转 `Number` | 修复 H2 下 `sys_session.sid` 登录插入失败 |
| `backend/src/main/java/com/dgp/seed/SourceDataSeeder.java` | 按方言生成自增主键 DDL，并把原表内索引改为独立 `CREATE INDEX`（容错已存在） | 兼容 H2 与 MySQL，同时保留演示源表索引 |
| `backend/src/main/java/com/dgp/report/ReportService.java` | 将“全域核心表”识别为全部有评分表，而非按字面值过滤 | 修复质量报告默认按钮生成 0 分、0 表的问题 |
| `backend/src/main/java/com/dgp/quality/StreamQualityService.java` | 在写流源表之前校验映射与报文主键，并要求主键进入字段映射 | 缺主键时稳定返回 400，避免 500 和脏数据 |
| `backend/src/main/java/com/dgp/migration/AggregationService.java` | 内部 H2 目标库使用 `MERGE ... KEY`，MySQL/PostgreSQL 分支保持不变 | 修复 UPSERT 刷新语法错误，重复刷新行数稳定 |
| `backend/src/main/java/com/dgp/standard/StandardController.java` | 落地率按 `COUNT(c.id)=0` 返回 0，避免除零 | 修复标准落地汇总接口 500 |
| `verify/flows_tenant.ps1` | 修正 PowerShell 7.6 HTTP 错误响应解析，增加 6 条租户 KPI 回归断言 | 避免 401 被误判，并覆盖子指标泄露 |
| `verify/flows_features.ps1`、`flows_agg.ps1`、`flows_ext.ps1`、`flows_core.ps1` | 修正 PowerShell 7.6 错误体解析与测试辅助函数 | 消除测试框架假失败，恢复真实断言 |

## 6. 测试边界与建议

- 远程 8093 不可达，未做目标网络、反向代理、生产数据库与真实账号的联调。
- 本轮共执行 7 个业务回归脚本，386 项断言全部通过；鉴权矩阵执行 912 次请求，未发现 5xx、网络失败或权限错配。
- `verify/flows_migration_v14.ps1` 依赖外部数据库/FTP/代理环境，本次未执行，相关跨网迁移能力仍需在目标网络复测。
- 租户隔离仍属于应用层 SQL 改写与显式关联过滤；新增业务表若包含 `tenant_id`，应补充对应租户回归用例。高风险生产部署建议叠加数据库行级安全或统一数据访问层。
- 会话安全测试会主动注销测试会话，不应在用户正在使用的共享账号上执行。
