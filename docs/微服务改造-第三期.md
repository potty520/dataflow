# 微服务改造 · 第三期（复杂调度 / XXL-Job）

## 架构

```
XXL-Job Admin (可选) ──触发──► dgp-scheduler 执行器
                                    │
                                    │ X-Scheduler-Token
                                    ▼
                              dgp-core /api/v1/internal/scheduler/**
                                    │
                     IntegrationService / QualityEngine / MetaCollect / Aggregation
```

- **本地模式（默认）**：`dgp-scheduler` 内 `LocalDueScanner` 每分钟拉到期任务并调用 core。
- **XXL 模式**：关闭本地扫描（`DGP_SCHEDULER_ENGINE=xxl`），由 XXL-Job Admin 触发 Handler。

## 环境变量

| 变量 | 说明 |
|---|---|
| `DGP_LOCAL_SCHEDULER` | core 内置调度，生产必须 `false` |
| `DGP_SCHEDULER_TOKEN` | scheduler ↔ core 共享令牌 |
| `DGP_SCHEDULER_ENGINE` | `local` / `xxl` |
| `DGP_XXL_ENABLED` | `true` 时启动 XXL 执行器（端口 9999） |
| `XXL_JOB_ADMIN` | Admin 地址，如 `http://127.0.0.1:8090/xxl-job-admin` |
| `DGP_CORE_URI` | core 基址，默认 `http://127.0.0.1:8082` |

## XXL Handler

| Handler | 参数 | 用途 |
|---|---|---|
| `dgpRunJob` | 作业 ID | 跑 ETL 作业 |
| `dgpRunWorkflow` | 工作流作业 ID | 触发工作流 |
| `dgpRunCollect` | 采集任务 ID | 元数据采集 |
| `dgpRunCheck` | 稽核 ID | 质量稽核 |
| `dgpRefreshAggregations` | 无 | 聚合刷新 |
| `dgpMarkOverdue` | 无 | 问题单超期 |
| `dgpResetDailyQuota` | 无 | 日配额清零 |
| `dgpScanDueAll` | 无 | **推荐**：每分钟扫描全部到期任务（替代 LocalDueScanner） |

平台侧可查建议注册列表：`GET /api/v1/scheduler/jobs`（含 `xxlHandler` / `xxlParam` / `suggestedCron`）。

DAG：在 XXL-Job Admin 用「子任务」串起多个 Handler（失败重试/超时在 Admin 配置）。

## Compose

```bash
# 基础设施 + 应用（本地扫描）
docker compose -f deploy/compose/docker-compose.yml up -d redis core auth gateway scheduler

# 启用 XXL Admin（需 MySQL 中先建 xxl_job 库并导入官方 tables_xxl_job.sql）
docker compose -f deploy/compose/docker-compose.yml --profile xxl up -d
```

然后：

```bat
set DGP_LOCAL_SCHEDULER=false
set DGP_XXL_ENABLED=true
set DGP_SCHEDULER_ENGINE=xxl
```
