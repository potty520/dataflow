# 功能说明：流式数据质检 + 数据迁移映射（v1.2）

> 本章说明两项新增能力的定位、数据模型、执行流程、接口与使用方式。
> 验收脚本：`verify/flows_features.ps1`（55 项断言，覆盖流式质检、数据迁移、实时推送、分批/续传/回滚）。

---

## 一、流式（微批）数据质检

### 1.1 定位

批式稽核（`qa_rule` + `qa_check`）针对"表当前快照"跑 SQL，适合 T+1；流式质检针对**贴源层新增数据**做准实时校验：

- 每个流源绑定一张表 + 一个**水位字段**（时间戳或自增序号）；
- 按 `window_seconds` 切窗口，每 5 秒调度一次，取「上一水位 ~ 当前水位」之间的新增行；
- 规则是**"不合格条件"布尔谓词**（如 `metric_value < -100 OR metric_value > 200`），引擎对窗口内数据计算总行数与不合格行数；
- 失败行占比超过容差 → 落 `qa_stream_result`（FAIL）并生成 `qa_stream_alert` 告警，可在页面处置。

> 不引入 Kafka/Flink：以"水位 + 定时微批"实现准实时。若接入真正的流（Kafka/Flink），只需替换"窗口取数"这一段，规则与结果模型可直接复用。

### 1.2 数据模型

| 表 | 说明 |
|---|---|
| `qa_stream_source` | 流源：表、水位字段/类型、窗口长度、批量上限、状态、`last_watermark`（当前水位） |
| `qa_stream_rule` | 规则：所属流源、维度、不合格条件（布尔谓词）、容差、级别、最近通过率 |
| `qa_stream_result` | 窗口结果：窗口起止、行数、失败行、通过率、状态（PASS/FAIL）、耗时 |
| `qa_stream_alert` | 告警：标题、级别、通过率、窗口、状态（OPEN/HANDLED）、处置人/时间 |

### 1.3 执行流程

```
调度器(每5s) → 扫描 ENABLED 流源
  → 计算窗口 [last_watermark, now]（时间戳）或 (last_watermark, max(id)]（数值）
  → 对每条 ENABLED 规则执行：
       SELECT COUNT(*)                                        -- 窗口总行数
       SELECT SUM(CASE WHEN (<不合格条件>) THEN 1 ELSE 0 END)  -- 不合格行数
  → 通过率 = (总行-不合格)/总行；≥ 1-容差 则 PASS，否则 FAIL
  → 写 qa_stream_result、回写规则最近值；FAIL 时按去重窗口生成告警
  → 窗口内有数据才推进 last_watermark（空窗口不推进，避免迟到数据被跳过）
```

### 1.5 安全校验

规则条件在保存时校验：禁止分号/注释（多语句）、禁止 `insert/update/delete/drop/alter/truncate/create/merge/grant/revoke/call`、禁止文件/外部访问函数（`CSVREAD`/`LOAD_FILE` 等），长度 ≤ 1000。表名与水位字段必须是合法标识符且可读（创建时执行 `SELECT col FROM table LIMIT 1` 验证）。

### 1.6 演示数据与使用

内置 2 个流源 / 5 条规则（`StreamMigSeeder`）：

| 流源 | 表 / 水位 | 规则 |
|---|---|---|
| SS-DEVICE-METRIC | `ods_device_metric` / `collect_time`，60s | 指标越界、设备编号为空、采集时间超前 |
| SS-ORDER-STREAM | `ods_order` / `order_time`，300s | 订单金额非正、客户编号为空 |

页面：**数据质量 → 流式质检**（每 5 秒自动刷新）。首次演示可点「重置水位」+「执行全部窗口」，把历史数据纳入首个窗口。


### 1.7 实时推送接入（v1.3，可与 Kafka 对接）

微批窗口适合贴源表；若数据以事件形式产生，可直接推送到平台做**事件级实时质检**：

1. 流源配置主键字段（`pk_col`），并在“推送接入”里配置字段映射：
   `{"device_id":"deviceId","metric_value":"value","collect_time":"collectTime"}`
2. 生产者（Kafka 消费者 / 业务系统 / 边缘网关）把消息体 POST 到
   `POST /api/v1/quality/stream/push/{sourceCode}`（需 Bearer 令牌）。
3. 平台按映射写入源表 → 对每条启用规则执行 `WHERE <pk>=? AND (<不合格条件>)` → 结果/告警落库（窗口为事件时间）。

Kafka 接入示例（消费者侧伪代码）：

```bash
kafka-console-consumer --bootstrap-server kafka:9092 --topic device-metric --from-beginning \
  | while read -r line; do
      curl -s -X POST "$DGP/api/v1/quality/stream/push/SS-DEVICE-METRIC" \
        -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' -d "$line"
    done
```

> 平台不引入 Kafka 客户端依赖，任何 MQ/流处理框架都可通过该 HTTP 入口接入；后续如需原生 Kafka 消费，只需在 `StreamQualityService` 增加 consumer 把消息转调 `pushEvent`。

## 二、数据迁移映射

### 2.1 定位

面向"源表 → 目标表"的结构化迁移：字段级映射（直接/表达式/常量/默认值）→ 预检（类型/样例/建表建议）→ 执行（`INSERT … SELECT`）→ 对账（行数/主键/空值/合计）→ 差异明细。

### 2.2 数据模型

| 表 | 说明 |
|---|---|
| `mig_project` | 迁移项目：源表、目标表、模式（FULL/INCREMENTAL）、水位字段、是否清空目标、状态 |
| `mig_mapping` | 字段映射：源字段/目标字段、转换类型、表达式、默认值、顺序 |
| `mig_check` | 对账项：ROW_COUNT / PK_DUP / NULL_RATE / SUM + 容差 |
| `mig_run` | 执行批次：状态、起止时间、源行数、目标行数、写入行数、失败行数、说明 |
| `mig_diff` | 对账差异：检查项、期望值、实际值、差异、结论、明细 |

### 2.3 转换类型

| 类型 | 含义 | 示例 |
|---|---|---|
| DIRECT | 源字段直取 | `customer_id → customer_id` |
| EXPR | SQL 值表达式（函数/CASE 等，保存时做安全校验） | `CONCAT('CK', customer_id)` |
| CONST | 写入固定常量 | `'dgp'` |
| DEFAULT | 源字段为空时的默认值 | `COALESCE(phone, '未知')` |

### 2.4 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/v1/migration/overview` | migration:project:view | 项目/映射/24h 执行/对账失败统计 |
| GET | `/api/v1/migration/tables`、`/tables/{table}/columns` | migration:project:view | 表与字段选项 |
| GET/POST/PUT/DELETE | `/api/v1/migration/projects[/{id}]` | view/create/edit | 项目管理 |
| GET | `/api/v1/migration/projects/{id}` | migration:project:view | 详情（含映射/对账项/最近批次） |
| GET | `/api/v1/migration/projects/{id}/recommend` | migration:project:view | **映射自动推荐**（名称相似度 + 类型族判断） |
| GET/POST | `/api/v1/migration/projects/{id}/mappings` | view/edit | 查询/保存映射（目标字段去重校验） |
| POST | `/api/v1/migration/projects/{id}/checks` | migration:project:edit | 保存对账项 |
| POST | `/api/v1/migration/projects/{id}/precheck` | migration:project:view | 预检（目标表是否存在、缺列、样例、建议 DDL） |
| GET | `/api/v1/migration/projects/{id}/statement` | migration:project:view | 生成迁移 SQL（可审计） |
| POST | `/api/v1/migration/projects/{id}/run` | migration:project:exec | 执行迁移（可选执行前清空目标表） |
| GET | `/api/v1/migration/projects/{id}/runs`、`/runs/{runId}` | migration:project:view | 执行记录/详情 |
| POST | `/api/v1/migration/projects/{id}/create-target` | migration:project:edit | 按映射一键创建目标表 |
| POST | `/api/v1/migration/runs/{runId}/reconcile` | migration:project:reconcile | 对账并写差异 |
| POST | `/api/v1/migration/runs/{runId}/rollback` | migration:project:exec | 增量批次回滚（按水位删除本次写入） |
| GET | `/api/v1/migration/runs/{runId}/diffs` | migration:project:view | 差异明细 |

### 2.5 推荐算法

对每个源字段，在目标字段中按名称打分：完全相同 100、忽略下划线相同 95、后缀包含 80、包含 70；归属同一类型族（字符串/整数/小数/时间/布尔）→ `DIRECT`，否则建议 `EXPR`（自动生成 `CAST(col AS …)`）。已匹配的目标字段不再重复分配。

### 2.6 对账类型

| 类型 | 校验内容 | 通过条件 |
|---|---|---|
| ROW_COUNT | 源/目标行数 | 相对差异 ≤ 容差 |
| PK_DUP | 目标主键重复数 | 等于 0 |
| NULL_RATE | 关键字段空值率（源 vs 目标） | 差值 ≤ 容差×100 |
| SUM | 数值字段合计（源 vs 目标） | 相对差异 ≤ 容差 |

### 2.7 演示项目

| 项目 | 源 → 目标 | 映射 | 对账项 |
|---|---|---|---|
| MIG-CUST-DIM | ods_customer → dwd_customer_dim | 11 条（含 `CONCAT('CK',…)`、年龄/日期派生） | 行数、主键重复、空值率、SUM |
| MIG-ORDER-FACT | ods_order → dwd_order_fact | 12 条（含日期 CAST、退款标记派生） | 行数、主键重复、SUM |

页面：**数据迁移**。流程：选项目 → 「自动推荐映射」或手工调整 → 保存 → 预检 → 执行 → 对账。


### 2.8 分批执行、断点续传与回滚（v1.3）

- **分批**：增量模式按 `batch_size`（项目配置或执行时传 `batchSize`）按水位切片，`SELECT MAX(wm) FROM (... LIMIT batchSize...)` 取下一批边界，逐批 `INSERT … SELECT` 并推进 `last_watermark`；执行记录 `chunk_count`。
- **断点续传**：每批成功即写回项目 `last_watermark`，中断后再次执行从该水位继续；可用 `mode=INCREMENTAL` + 重置水位重跑。
- **回滚**：`POST /runs/{runId}/rollback` 仅增量批次可用，按映射解析目标端水位列，删除本次起始水位之后的写入；首批次（起始水位为空）删除 `<= end_watermark` 的数据。全量批次不支持回滚（无起始水位）。
- **一键建表**：目标表不存在时，`POST /projects/{id}/create-target` 按映射类型生成并执行 DDL（VARCHAR/BIGINT/DECIMAL/DATETIME）。
- **失败自动回滚**：项目 `rollback_on_fail=1` 时，增量执行异常会自动删除本批次写入并记录 `rollback_status=ROLLED_BACK`。

## 四、已知限制与 Roadmap

- 流式质检是**微批**实现（窗口 5s 调度粒度），非事件级实时；接入 Kafka/Flink 时为 `StreamQualityService` 增加流式 connector 即可。
- 迁移目前限定**同一数据源内**的源表→目标表；跨实例迁移需要按 `md_datasource` 建立第二数据源连接（表结构与接口已预留 datasource 字段）。
- 迁移执行的批次为**单事务大 SQL**（`INSERT … SELECT`），超大表建议按水位分批（INCREMENTAL 模式已支持水位）。
- Roadmap：Kafka 源、窗口聚合函数（去重计数/滑动窗口）、迁移断点续传与回滚、迁移前后抽样逐行比对报告。
