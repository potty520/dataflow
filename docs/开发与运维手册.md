## 1. 快速启动

| 方式 | 命令 | 访问地址 |

| 一体化（推荐） | 双击 `start-backend.cmd`（或 `bash start.sh`） | http://127.0.0.1:8080 |

### 真实执行点（非静态演示）

1. **元数据采集**：读取 `information_schema.tables/columns/key_column_usage`，计算真实行数并按 210 B/行估算存储，差异写回 `md_table/md_column`，同时生成采集实例记录。
2. **质量稽核**：规则表达式为真实 SQL，引擎在源数据层执行并回写通过率、评分、`qa_check_result`、自动建单。
3. **ETL 执行**：作业脚本为可执行 SQL（DELETE/INSERT SELECT/UPDATE），运行时逐语句执行并统计影响行数、写运行日志与实例。
4. **自助取数 / API 调用**：真实查询 H2 源表，按 `sec_mask_policy` 对输出列脱敏，记录 `svc_call_log` 并扣减配额。
5. **敏感识别**：内容方式对 200 条样本做正则命中率统计，≥60% 判定敏感并给出脱敏样例。
6. **审计链**：每条写操作计算 `hash = SHA256(prevHash|user|action|resource|time)`，`/audit/verify-chain` 逐条复算。
7. **SQL 血缘**：解析 `INSERT INTO ... SELECT ... FROM/JOIN`，抽取表级与字段级映射并可落库。

### 源数据质量缺陷（用于验证稽核有效性）

`ods_customer` 注入空手机号/空城市/非法邮箱/未来生日/重复证件号；`ods_order` 注入负金额、超上限金额、已支付但无支付时间、非法状态；`ods_payment` 注入重复交易号、金额不一致；`ods_device_metric` 注入空值、量程越界、采集滞后；`ods_gov_population` 注入证件号缺失与长度非法。当前实测：综合质量分 **84.68**（一般），24 条规则中 21 条通过，时效性维度 54.75% 暴露设备采集滞后问题。

## 4. 接口与数据约定（对齐 00 基线 §6）

- 统一响应体：`{"code":0,"message":"ok","data":{},"traceId":"...","timestamp":1786...}`
- 分页：`pageNum`/`pageSize`（默认 1/20，上限 200）；响应 `records/total/pageNum/pageSize/pages`
- 错误码分段：10000+ 通用、20000+ 元数据、21000+ 建模、22000+ 标准、23000+ 集成、24000+ 质量、25000+ 安全、26000+ 服务、27000+ 行业包、50000 内部
- 认证：`Authorization: Bearer {accessToken}`，`X-Tenant-Id` 租户头，`X-Trace-Id` 链路头
- 权限：`{模块}:{资源}:{操作}`，后端 `@RequirePerm` 与前端菜单/按钮共用同一编码
- 开放通道：`/open/v1/{apiPath}` 独立于内部 `/api/v1`，`X-App-Code`/`X-App-Secret` 或 `Bearer AT-*`
- 完整接口清单：登录后访问「系统管理 → 接口清单」，或运行后查看 `docs/API清单.md`（当前 **258** 个接口路径 / 15 个能力域，含权限编码）

## 5. 与基线的差异说明（评审项）

本机无 JDK/Maven/Docker/PostgreSQL，且交付目标为**可运行、可验收**的完整实现，因此对基础设施层做了等价替换；**接口契约、领域边界、响应体、错误码、权限编码、租户模型、表命名规范均严格对齐**基线。

| # | 基线要求 | 本交付实现 | 影响与回归路径 |
|---|---|---|---|
| 1 | 14 个 Spring Boot 微服务 + Nacos + Gateway | **单进程 `dgp-boot`**，包结构按 `com.dgp.<domain>` 与端口一一对应（系统管理页可见服务清单） | 领域代码零改动即可按包拆分为独立服务；网关鉴权逻辑现由 `AuthInterceptor` 承担 |
| 2 | PostgreSQL/达梦/Kingbase | 开发 H2（文件模式，PostgreSQL 兼容语法）；生产 `application-prod.yml` 直接切 PostgreSQL | DDL 未使用任何库独有语法，切换仅改连接串 |
| 3 | MyBatis-Plus | Spring JDBC + 轻量 `Db` 门面（列名自动转驼峰） | Mapper 层可替换，SQL 已集中在 Controller/Service |
| 4 | JWT RS256 + 双令牌轮换 | HS256（单进程无跨服务密钥分发场景），**access 30min / refresh 7d**，`typ` 声明区分两类令牌、登出写 jti 黑名单立即失效 | 替换 `JwtService.sign/verify` 即可切 RS256；生产必须通过 `DGP_JWT_SECRET`（≥32 字节）注入密钥，否则启动失败 |
| 5 | Elasticsearch 百万级检索 / NebulaGraph 血缘 | SQL `LIKE` 检索 + 邻接表血缘；已做层级懒加载（`level` 参数）与图查询缓存 | 数据层替换，接口出参结构不变 |
| 6 | 前端 qiankun 微前端 + 14 子应用 | **单 Vue 应用**，路由与页面按 `dgp-web-*` 域划分；Vite 构建 `es2019` | 子应用可按 views 目录整体迁出注册 qiankun |
| 7 | 血缘图 AntV G6 / 设计器 LogicFlow | ECharts `graph` 力导向图 / 自研 SVG 流程画布 | 组件替换，数据契约不变 |
| 8 | Word/PDF 导出（POI/OpenPDF） | HTML（Word 可直接打开）+ CSV + Markdown | 接入 POI 后复用 `ReportService` 上下文 |
| 9 | DolphinScheduler / Spark / Flink / Kafka | 内置调度器（60s 扫描）+ JDBC 执行器，语义等价（触发/依赖/重试/超时/日志） | 引擎提交接口已按 `engine-batch` 抽象 |
| 10 | 演示数据 | 由 `seed` 包确定性构造（固定随机种子），非生产数据 | 生产 `dgp.seed-demo-data=false` |

**未实现项（明确缺口）**：跨租户血缘穿透授权仅保留接口与授权记录，未做真实跨库穿透；**多租户行级隔离仍未注入 SQL**（涉及 60+ 张表与全部查询，需单独迭代；当前以角色权限 + 数据域配置隔离，生产启用多租户前必须补齐）；脱敏审批的 unmask 申请未实现原文回传通道（合规考虑）；行业包上传仅支持 manifest JSON（未做 ZIP 分片与签名校验）；未接入 Flyway/Liquibase（生产首次需手工执行 `schema.sql`）；定时表达式仅解析"分/时"为固定值的 cron（如 `0 0 2 * * ?`），复杂表达式回退为 `intervalMin`。

## 7. 运维与排障

- 日志：`backend/logs` 之外输出到控制台，格式含 traceId；启动失败优先看 `seed` 阶段异常。
- 数据重置：停止服务后删除 `backend/data/dgp.mv.db`，重启即重新装载。
- 端口冲突：`java -jar target/dgp-boot.jar --server.port=8088`，并同步修改 `frontend/vite.config.js` 代理。
- 生产切换：`--spring.profiles.active=prod` 并注入 `DGP_DB_*` 环境变量；首次需先执行 `schema.sql`（或接入 Flyway）。
- 生产必填环境变量：`DGP_JWT_SECRET`（≥32 字节）、`DGP_MASK_KEY`；`DGP_CORS_ORIGINS` 按实际前端域名收紧。

## 11. 使用 MySQL 作为后台库（已实测）

`application-mysql.yml` 提供 MySQL 8 专用 profile；由于 H2/PG 与 MySQL 的 DDL 方言不同，仓库内单独提供 **`schema-mysql.sql`（由脚本自动生成，勿手改）**。

### 11.1 生成 DDL

```powershell
python deploy/gen_mysql_schema.py     # 由 schema.sql 生成 schema-mysql.sql
```
转换规则：`BIGINT … GENERATED BY DEFAULT AS IDENTITY` → `AUTO_INCREMENT`；独立的 `CREATE [UNIQUE] INDEX` → 内联 `KEY/UNIQUE KEY`（MySQL 8 不支持 `CREATE INDEX IF NOT EXISTS`，内联后可随 `CREATE TABLE IF NOT EXISTS` 幂等）；`TIMESTAMP` → `DATETIME`（避免 MySQL 隐式默认/自动更新）；追加 `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4`。

### 11.2 建库建账号并校验 DDL

```powershell
$env:DGP_DB_NAME="dgp"; $env:DGP_DB_USER="dgp"; $env:DGP_MYSQL_PASSWORD="<强口令>"
python deploy/setup_mysql.py            # 建库/建用户/授权/执行 schema-mysql.sql/连通性校验
python deploy/setup_mysql.py --reset    # 删库重建（清空演示数据，用于重新种子）
```
生成的账号为 `'dgp'@'127.0.0.1'`（仅本机 TCP 可连）。

### 11.3 部署（profile 由环境变量开启）

```powershell
$env:DGP_DB_PASSWORD="<同上的口令>"; $env:DGP_DB_NAME="dgp"; $env:DGP_DB_USER="dgp"
python deploy/remote.py deploy backend/target/dgp-boot.jar 8092
```
部署脚本会把 `SPRING_PROFILES_ACTIVE=mysql` 与 `DGP_DB_*` 写入 `/opt/datagov/datagov.env`（600）；不设置 `DGP_DB_PASSWORD` 时保持 H2 形态。

### 11.4 MySQL 适配要点（代码层）

| 项 | 处理 |
|---|---|
| 自增列 | 两处运行期裸 DDL（`SourceDataSeeder` 的 ODS 表）改用 `AUTO_INCREMENT`，H2/MySQL 通用 |
| 字符串拼接 | `\|\|` 改为 `CONCAT(...)`；同时连接初始化设置 `PIPES_AS_CONCAT` 兜底 |
| `CAST(x AS INT/VARCHAR)` | MySQL 不支持该 CAST 目标；改为数值表达式或 `TIMESTAMPDIFF` 等可移植写法 |
| 保留字 | `SELECT … AS rows` 在 MySQL 8 报错（`ROWS` 保留字），改为 `row_cnt` |
| 元数据采集 | `information_schema` 的库名可配：`dgp.meta.schema`（MySQL 为库名 `dgp`，H2/PG 为 `public`），并去掉 H2 专有 `ESCAPE '\'` |
| 会话参数 | `connection-init-sql`：`PIPES_AS_CONCAT`、`max_execution_time=60000`、`innodb_lock_wait_timeout=10` |
| 并发写 | ETL 作业改为**全局串行锁**（2s 未拿到即返回"作业运行中"），避免多作业写同批 DWD 表互相等锁 |
| ETL 性能 | `dwd_order_fact(order_id,status)`、`ods_payment(order_id,status)` 建索引；`JOB-PAY-SYNC` 由 40s 降至 0.23s |
| 种子幂等 | 新增 `seed.completed` 完成标记，避免"种子中途失败 → 下次启动因 sys_user>0 静默跳过"的半装载状态 |

### 11.5 MySQL 运维

```bash
# 查看库状态
mysql -N dgp -e "SELECT COUNT(*) FROM md_table; SELECT COUNT(*) FROM ods_order;"
# 备份 / 恢复
mysqldump --single-transaction --default-character-set=utf8mb4 dgp > /opt/datagov/dgp-$(date +%F).sql
mysql dgp < /opt/datagov/dgp-2026-10-21.sql
# 重新种子（演示数据）
python deploy/setup_mysql.py --reset && systemctl restart datagov
```

**已实测结果**：MySQL 8.0.46 + utf8mb4；77 张表、13 张元数据表/111 字段/11.3 万行 ODS 数据、24 条质量规则（真实执行 90.66 分）、7 个 ETL 作业全部 SUCCESS、元数据采集读到 13 张表、`verify.ps1` **PASS=72 FAIL=0**；浏览器登录/9 个页面巡检 0 console 错误、0 失败请求。

## 12. 并发调优与 nginx 入口（已实测）

单机 1 vCPU 的容量优化见 [docs/并发容量报告.md](docs/并发容量报告.md)，要点：

- **鉴权缓存**：每请求 3 次鉴权查询 → 0 次（黑名单内存化 10s 对齐、用户 30s、权限 60s，变更即时失效）
- **聚合缓存**：概览看板等 8 个重查询接口加 `TtlCache`（8~20s），写操作统一失效；看板 17 → 2324 QPS
- **运行时**：Tomcat 400 线程 / 1000 排队 / 60s keepalive；Hikari 24 连接
- **nginx（8093）**：静态资源 `sendfile + gzip_static`（部署时预压缩）+ 一年强缓存；API 反代保持 keepalive；`chunked_transfer_encoding off` 避免公网分块截断；部署脚本自动同步静态资源
- 登录受 PBKDF2 210k 限制（1 核约 2.8 次/秒），未降低安全强度

